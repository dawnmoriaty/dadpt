Scope: Projects utilizing Golang for Backend and TypeScript/React TanStack for Frontend. Core Philosophy: Total Type Safety from the Database (SQL) to the UI Component.
A. Backend (Golang): SQL-First & Generated DAOs
• Database Workflow (Schema-First):
◦ Mandate: Define SQL and Migrations first. Use sqlc to generate type-safe Go code. Never write manual Data Access Objects (DAOs),.
◦ Execution: Do not run raw goose or sqlc commands. You must use a standardized Makefile as the entry point for all generation and migration tasks to ensure environment consistency,.
• Code Generation Config:
◦ Mandate: Configure sqlc with emit_json_tags: true (to reuse structs for API responses) and emit_interface: true (to enable easy mocking in Unit Tests).
• Error Handling & Concurrency:
◦ Sentinel Errors: Define errors as package-level variables (var ErrNotFound = ...) rather than dynamic strings. This allows the frontend/handler to map errors to specific HTTP Status Codes (e.g., 404 vs 409) reliably,.
◦ Concurrency: Use errgroup.Group instead of sync.WaitGroup. This ensures context cancellation propagation—if one goroutine fails, the entire operation cancels immediately to save resources.
B. Frontend (TypeScript React TanStack): File-Based & Validated
• Routing Workflow ("Create-Gen-Fix"):
◦ Mandate: Strictly follow File-Based Routing. Do not write route definitions manually in code.
◦ Process: 1. Create: Create a new file/folder (e.g., routes/posts/$postId.tsx). 2. Gen: Allow the TanStack plugin to auto-generate the routeTree.gen.ts. 3. Fix: Use the generated createFileRoute function to implement logic with full type safety.
• Data Validation:
◦ Search Params: Never read URL Search Params as any or raw string. You must validate them using zod schemas inside the validateSearch option of the Route. This ensures "Trusted Input" for your components,.
◦ Query Keys: Use a Query Key Factory pattern. Do not hardcode strings for TanStack Query keys; this prevents cache invalidation bugs caused by typos.
C. Integration Protocol
• Contract: The Backend returns standard Sentinel Errors (mapped to HTTP codes). The Frontend consumes JSON (generated by sqlc tags) that aligns perfectly with TypeScript interfaces, creating a closed loop of type safety.
